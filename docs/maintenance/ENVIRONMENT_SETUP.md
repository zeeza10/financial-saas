**Purpose:** Explain how a developer or agent sets up a local environment safely, without production secrets.

**Related:** `SECRETS_MANAGEMENT.md`, `DEPLOYMENT.md`, `TESTING_STRATEGY.md`, `AI_WORKFLOW.md`

This describes the intended setup; the repository does not contain application code yet.

## 1. Prerequisites
Node.js LTS, a package manager (pnpm proposed), Git, Docker (for local Supabase), Supabase CLI, Cloudflare Wrangler.

## 2. Steps (intended)
1. Clone the repository; read `AGENTS.md` and `docs/ai/AI_CONTEXT.md`.
2. Copy `.env.example` to `.env.local`; fill with **local** values only (local Supabase URL and keys generated by the CLI). Never copy production values.
3. Start local Supabase; apply migrations to the local database; seed synthetic canary organizations.
4. Install dependencies from the lockfile (no ad-hoc installs).
5. Run `lint`, `typecheck`, unit tests, pgTAP tests, then start the Worker and the web app locally.

## 3. Rules
- `.env*` files (except `.env.example`) are ignored by Git; pre-commit hook runs secret scanning.
- Local databases contain synthetic data only.
- AI agents run in sandboxes without production credentials (`AI_SECURITY_RULES.md`).
